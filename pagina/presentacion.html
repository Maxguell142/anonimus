01 // VISIÓN DE INGENIERÍA

Contexto del Proyecto e Ideas Fundamentales

¿De dónde nace Anonymous? Comprende el origen del software, la integración armónica de 5 proyectos de código abierto y los pilares arquitectónicos que guían su diseño.

🎯 El Origen: Fusión y No Fragmentación

En la industria de la seguridad informática contemporánea existe una profunda fragmentación de herramientas: los auditores deben utilizar una utilidad para escanear puertos, otra para registrar notas, navegar por internet para consultar los marcos normativos de OWASP y recurrir a scripts adicionales para redactar el informe final.

El proyecto Anonymous no nació como un script aislado, sino como la fusión, orquestación y síntesis de cinco proyectos de vanguardia. Se seleccionaron los mejores patrones de cada iniciativa para crear un núcleo homogéneo que actúa simultáneamente como auditor ofensivo, asesor defensivo y asistente de operaciones tácticas.

Misión Central: Ofrecer un entorno de ciberseguridad unificado que no requiera servidores en la nube obligatorios ni infraestructuras pesadas de virtualización.

💡 La Filosofía Técnica: Rendimiento y Simbiosis

Mientras que las suites modernas de auditoría y los asistentes de inteligencia artificial exigen estaciones de trabajo de 32 o 64 GB de RAM, Anonymous se diseñó con una restricción estricta de ingeniería: debe ejecutarse con absoluta soltura en una laptop estándar para estudiantes o desarrolladores con 8 GB de RAM y procesador Ryzen 5 o Intel Core i5.

Asimismo, introduce la simbiosis Red Team + Blue Team: en lugar de limitarse a indicar qué puertos o servicios están abiertos, el sistema los correlaciona en tiempo real con las contramedidas formales de OWASP Top 10, MITRE ATT&CK y CIS Controls, cerrando el ciclo de seguridad de forma constructiva.

Privacidad y Persistencia: Base de datos relacional local en SQLite y documentación persistente tipo LLM Wiki formateada en Markdown para Obsidian.

Los 5 Pilares de Código Abierto Ensamblados en Anonymous:

⚔️ PentestGPT // Árbol de Tareas de Pentesting (PTT)
MOTOR OFENSIVO (RED TEAM)

En lugar de disparar comandos desordenados, PentestGPT aporta la metodología del Pentesting Task Tree (PTT): una estructura jerárquica de tareas dependientes que modela cómo piensa un auditor ético experimentado.

  • ✔ Fases secuenciales: Reconocimiento ➔ Escaneo ➔ Enumeración ➔ Análisis de Vulnerabilidad ➔ Reporte.
  • ✔ Progresión de estado: Cada tarea transita de pendiente a en progreso y completada tras verificar los resultados.
  • ✔ Adaptado a Python Nativo: Implementado en anonymous/engines/red/ptt.py sin dependencias pesadas ni llamadas a APIs bloqueantes.
# anonymous/engines/red/ptt.py class PTTNode: def __init__(self, id, phase, title, status): self.id = id self.phase = phase self.title = title self.status = TaskStatus.PENDING self.subtasks = [] # Transición automática: ptt_engine.complete_task("T2") # Escaneo completado ptt_engine.activate_task("T3") # Enumeración iniciada
🛡️ Cybersecurity-RAG // Asesor Normativo
MOTOR DEFENSIVO (BLUE TEAM)

Aporta el conocimiento normativo defensivo para que la plataforma no sea un simple generador de alertas, sino un asesor técnico de remediación basado en los marcos internacionales más reconocidos de la industria.

  • ✔ OWASP Top 10 (2021): Cobertura de A01 (Control de Acceso), A02 (Criptografía), A03 (Inyección), A05 (Mala Configuración).
  • ✔ MITRE ATT&CK: Técnicas de adversarios (T1046 Network Service Discovery, T1190 Exploit Public-Facing App, T1059 Command Scripting).
  • ✔ CIS Controls v8: Medidas concretas de endurecimiento de activos y líneas base de configuración.

🦺 ECC AgentShield // Arnés de Contención Ética
GOBERNANZA & HITL

Heredado del framework ECC (.agents), AgentShield es el guardián ético y de seguridad del sistema. Implementa el principio inquebrantable de Human-In-The-Loop (HITL) y la gestión de presupuesto de contexto (Context Budget).

  • ✔ Barrera de Contención HITL: Impide que cualquier escaneo o comando a destinos no locales se ejecute sin la aprobación explícita de un humano.
  • ✔ Presupuesto de Contexto: Poda y comprime logs para no saturar tokens de modelos de lenguaje ni permitir desbordes de memoria.
  • ✔ Cumplimiento Legal: Garantiza que el software nunca actúe como un malware autónomo o botnet fuera de control.
# anonymous/guardrails/agent_shield.py class AgentShield: def check_permission(self, target: str, confirmed: bool) -> bool: if target in ("127.0.0.1", "localhost"): return True # Seguro para pruebas locales if not confirmed: raise HITLAuthorizationRequired( f"Destino no local {target} requiere confirmación humana." ) return True
🚫🐳

Regla Estricta "No Docker"

Docker Desktop en Windows 11 requiere activar WSL2 o Hyper-V, consumiendo de 3 a 5 GB de RAM solo en iniciar el subsistema Linux. Anonymous elimina Docker por completo: utiliza sockets directos de Python que consumen menos de 60 MB en memoria, permitiendo que la computadora del usuario permanezca rápida, fresca y silenciosa.

💻📱

Arquitectura Híbrida Dual

No fuerza una elección binaria entre consola o gráficos: analistas veteranos pueden operar por CLI mediante python run.py con salida formateada en rich para Warp Terminal, mientras que instructores, estudiantes o clientes pueden disfrutar del HUD interactivo web en python server.py --port 8080.

📶🌐

Transmisión Abierta por Wi-Fi

El servidor HTTP nativo escucha en la dirección comodín 0.0.0.0:8080. Esto permite que el panel de control se proyecte de forma inalámbrica a smartphones, tablets u otras laptops en el aula o laboratorio sin necesidad de configuraciones complejas, cables ni routers corporativos.

🧠📚

LLM Wiki Persistente

A diferencia de los chats de IA efímeros que olvidan el contexto al cerrar la ventana, Anonymous almacena sus hallazgos, conceptos y metodologías en una Wiki estructurada en Markdown para Obsidian, asegurando trazabilidad histórica acumulativa entre sesiones.

02 // IMPACTO Y RELEVANCIA

¿Qué Problema Resuelve en el Mundo Real?

La ciberseguridad actual sufre de barreras de costos, fragmentación operativa y riesgos legales. Descubre cómo Anonymous resuelve cada uno de estos desafíos tangibles.

DESAFÍO 01

La Fragmentación Crónica de Herramientas de Auditoría

EL PROBLEMA EN EL MUNDO REAL

Para auditar un sistema, un especialista suele tener abiertas 4 a 6 aplicaciones independientes: un terminal con nmap, un bloc de notas para llevar la bitácora del árbol de tareas, dos pestañas del navegador para leer documentación en OWASP y MITRE, y un generador de PDFs.

"El analista pasa el 40% de su tiempo copiando y pegando datos entre herramientas inconexas, perdiendo la visión integral de la intrusión."
LA SOLUCIÓN DE ANONYMOUS

Centraliza el ciclo completo en un único flujo coherente: el escaneo por sockets puebla automáticamente el Árbol de Tareas PTT, registra el evento en la base de datos de hallazgos, despliega la ficha de mitigación normativa en un clic y permite exportar el informe estructurado sin salir de la plataforma.

"Flujo unificado: Un escaneo TCP alimenta el PTT, activa la correlación RAG y guarda el hallazgo con latencia en milisegundos."
DESAFÍO 02

La Barrera Excesiva de Hardware y Costos de Infraestructura

EL PROBLEMA EN EL MUNDO REAL

Las suites modernas de pentesting asistido por IA suelen requerir estaciones de trabajo de 32 o 64 GB de RAM, tarjetas gráficas dedicadas para modelos locales y contenedores Docker gigantescos (de 10 a 20 GB). Esto deja fuera a estudiantes universitarios, investigadores de países en desarrollo y pequeñas empresas.

"Equipos con 8 GB de RAM quedan congelados al intentar iniciar entornos de laboratorio basados en máquinas virtuales y Docker."
LA SOLUCIÓN DE ANONYMOUS

Democratización del aprendizaje y la práctica: Escáner TCP construido con sockets directos en C/Python, base de conocimiento en memoria y servidor HTTP nativo. Consume menos de 60 MB de RAM y corre con fluidez en computadoras estándar con Windows 11 o Linux.

"100% Nativo: Funciona en laptops económicas de 8 GB sin sobrecalentar el procesador ni degradar la batería."
DESAFÍO 03

El Peligro de Daños No Intencionados y Responsabilidad Legal

EL PROBLEMA EN EL MUNDO REAL

La integración de agentes autónomos de IA en ciberseguridad plantea un grave riesgo: un modelo desbocado o un comando mal interpretado puede atacar servidores de producción, bases de datos gubernamentales o pasarelas de pago de terceros, generando caídas de servicio y demandas penales.

"Una IA sin guardarraíles éticos que escanea una subred pública puede ser considerada un ciberataque bajo leyes informáticas."
LA SOLUCIÓN DE ANONYMOUS

AgentShield con Human-In-The-Loop (HITL) forzado: Todo intento de auditar un host que no sea localhost o la IP propia es interceptado en el núcleo antes de generar ningún paquete de red. La acción queda suspendida en el modal de confirmación hasta que el operador humano la valida.

"Seguridad por diseño: Ni un solo paquete sale hacia redes no autorizadas sin consentimiento humano formal."
DESAFÍO 04

La Brecha entre el Ataque (Red) y la Remediación (Blue)

EL PROBLEMA EN EL MUNDO REAL

Generalmente, los pentesters informan "el puerto 8080 está abierto" o "el servicio expone cabeceras inseguras", pero el equipo defensivo tarda semanas en averiguar cómo parcharlo de acuerdo con los marcos de cumplimiento requeridos por la dirección.

"Reportar una vulnerabilidad sin proporcionar el código de endurecimiento deja a la organización expuesta por semanas."
LA SOLUCIÓN DE ANONYMOUS

Enlace simbiótico instantáneo: Por cada puerto o servicio detectado, el asesor Blue Team despliega de inmediato la ficha con la causa raíz y las instrucciones de remediación concretas (OWASP A01/A05, MITRE T1046, reglas UFW/iptables y directivas CSP/HSTS).

"De la detección al parche: Instrucciones de endurecimiento técnico entregadas en el mismo segundo del hallazgo."
